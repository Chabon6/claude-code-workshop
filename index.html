90 MIN · WORKSHOP · CLAUDE CODE

From Work to Skill

把你反覆解釋給 Claude 的工作流程、判斷標準與品質要求，轉化為可重複使用的 Skill；再理解如何讓工作在正確的時機自動發生。

1個可帶回工作的 Skill
2種測試：正常 + 困難
3個核心：Create · Improve · Automate
Course Objective

今天不教你背 Skill 語法。

今天要學的是：如何把自己的工作 know-how 明確化，讓 Claude 能在之後的任務中重複使用，而不是每次重新 prompt。

時間內容目標
0–10為什麼 Skill 值得學從 repeated prompting 看見可重複能力的價值
10–25Skill 基本觀念 + Skill Creator理解 Skill 如何被觸發、載入與組成
25–40工作知識如何轉成 Skill區分步驟、判斷、例外與品質標準
40–65Hands-on用官方 Skill Creator 建立自己的 Skill
65–75Test & Improve用真實情境找出 Skill 的不足並迭代
75–87Automation理解 Skill 如何接到排程與觸發
87–90Wrap-up找到下一個值得 Skill 化的工作
01 · Why Skills

如果你一直在教 Claude 同一件事，就不該一直重打同一段 Prompt。

Skill 的價值，是把重複出現的 instructions、流程與 know-how 保存成可重複使用的能力。

Repeated Prompting

每次重新解釋

「記得比較上週」、「只列重要事項」、「不要只是摘要」、「最後幫我 QA」……

Reusable Skill

保存工作方法

Claude 在相關任務出現時載入固定的工作方法、判斷規則、資源與交付標準。

起點問題

What do you repeatedly tell Claude? 重複指令通常就是最容易找到的 Skill 原料。

02 · Skill Basics

Skill 不是「一個很長的 Prompt」。

最低限度是一個含有 SKILL.md 的資料夾；需要時可加入 scripts、references、assets。

my-skill/
├── SKILL.md          # 必要：metadata + instructions
├── scripts/          # 選配：需要穩定執行的程式
├── references/       # 選配：需要時才讀的參考資料
└── assets/           # 選配：模板、圖示、輸出資源
A

Description = Triggering signal

描述「這個 Skill 做什麼」以及「何時應使用」。它是 Claude 判斷是否啟用 Skill 的重要訊號。

B

Instructions = 工作方法

真正使用 Skill 時才載入主體 instructions；references 等資源則按需要再讀。

Progressive disclosure

課堂真正要學的

Claude 可以協助建立 Skill；你真正需要提供的是 Claude 不知道的：判斷、例外、品質門檻與上下文。

放在哪裡？

Project Skill

.claude/skills/
跟著 repository 分享給團隊；適合專案／組織工作流程。

User Skill

~/.claude/skills/
個人跨專案使用；適合自己的工作方法。

Starter Prompt
Use the skill-creator skill to help me turn the following recurring work into a reusable Skill.

Do not draft immediately. First interview me about:
- when this task should trigger
- inputs and outputs
- how I make decisions
- exceptions and edge cases
- what bad output looks like
- what “good enough to send” means

My recurring task is: [describe your task]
04 · Knowledge Transfer

不要只描述 Task。要把 Judgment 教出去。

Skill 的價值不是字數，而是它保存了多少 Claude 原本不知道、但有經驗的人會使用的 know-how。

1

Steps

事情依什麼順序做？哪些步驟不可跳過？

2

Judgment

怎麼判斷重要、不重要、正常、異常、是否要深入？

3

Exceptions

哪些情況不能套一般規則？資料衝突時怎麼處理？

4

Definition of Done

什麼品質才真的可以交給主管、客戶或下一個流程？

Thin Skill 
Review the data carefully.
Identify important trends.
Be professional and accurate.
Double-check your work.
Knowledge-rich Skill 
Prioritize by business impact, not percentage change alone.
Separate confirmed facts from hypotheses.
Escalate conflicting sources instead of silently choosing one.
Do not deliver until material numbers reconcile to source.
四個訪談問題

① What do you repeatedly tell Claude? ② What do you know that Claude doesn't? ③ What mistakes would a junior make? ④ What does “good enough to send” mean?

05 · Hands-on · 25 min

把一件真實工作變成 Skill。

不要選「看起來很酷」的案例。選你真的做過、之後還會再做，而且你知道好壞差異的工作。

1

Pick

選一個會重複出現、已有做法、結果有品質差異的工作。

2

Teach

讓 Skill Creator 訪談你；優先提供真實例子、判斷、例外與 bad output。

3

Build

讓 Skill Creator 起草；review 它是否真的捕捉到你的工作方法。

Hands-on Checklist
  • 我選的是一件自己真的做過的工作。
  • 我至少提供一個實際 input / output 或具體情境。
  • 我提供至少一條不是照 SOP 就能知道的判斷規則。
  • 我說明至少一個例外或容易犯錯的地方。
  • 我定義了什麼叫「可以直接交付」。
06 · Test & Improve · 10 min

第一版 Skill 不需要完美；它需要可被挑錯。

至少測一個正常情境 + 一個需要判斷、資料缺漏或來源衝突的困難情境。

Normal case

輸入完整、情境典型。確認 Skill 是否被正確使用，以及 workflow 是否順利。

Difficult case

資料缺失、來源矛盾、例外、需要 judgment。這裡最容易暴露 Skill 的真正不足。

Debug the right layer

症狀通常要改哪裡
該用卻沒用Description / triggering
用了但做法不對Workflow / decision rules / references
看似合理但不能交Definition of done / quality checks / examples
最重要的 Review 問題

Would I actually send this output at work? 如果不能，請把「為什麼不能交」直接回饋給 Skill Creator。

07 · Automation · 12 min

Skill 解決 HOW；Automation 解決 WHEN。

Skill 讓工作可重複。排程或觸發機制，才讓工作在你沒有手動提醒 Claude 時發生。

方式適合什麼
Cloud Routines需要在 Anthropic cloud 定期或被事件觸發執行
Desktop scheduled tasks需要讀本機檔案、工具或本地環境
/loop目前 session 中的短期 polling / 臨時重複檢查
一個重要差異

Skill 本身不是排程器。它定義「怎麼做」；Routine / schedule / trigger 定義「什麼時候做」。

Instructor Cases

案例區先保留。

之後放你的 2–3 個真實案例；建議刻意選不同成熟度，而不是三個不同主題的報告 Skill。

Case A · Simple

Repeated prompt / checklist → reusable Skill。

Case B · Judgment-heavy

Tacit knowledge / decision rules / exceptions。

Case C · Automated

Skill + trigger / routine → autonomous workflow。

Wrap-up

選你的下一個 Skill。

  • 這件事之後還會再發生嗎？
  • 我是否每次都在重複解釋類似 instructions？
  • 這件事有「新人不知道、我知道」的 judgment 嗎？
  • 好結果與壞結果之間，有可說清楚的差異嗎？

Create → Test → Automate

“You don't need to know how to write a Skill. You need to know how to teach Claude your job.”

Skill Creator 可以幫你寫；真正不可取代的是，你能不能把自己的工作方法、判斷與標準講清楚。
